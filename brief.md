## Project Identity

| Field | Value |
|-------|-------|
| **Purpose** | Recovered Diablo II: LoD 1.14d C++ source (fork of jaenster/redivivus) plus a hand-written "Vanilla+" fix-and-QoL layer maintained directly in the source; ships as `d2vp.exe`, single-player only. |
| **Tech Stack** | C/C++ (MSVC x86 ABI), mingw-w64 i686 g++ (llvm-mingw on the owner's Win11), CMake 3.24 + Ninja, GNU make-style module libs linked whole in 1.14d link order; libbacktrace for crash symbolisation. |
| **Entry Point** | `Source/Game/Main.cpp` (`WinMain`-equivalent, boot sequence at :1145–1265); boot marks land in `d2boot.log` via `Redivivus/d2_boot.cpp`. |
| **Build/Run** | `cmake -S . -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-i686.cmake && cmake --build build` → `build/d2vp.exe`. Needs a real 1.14d install (MPQs) at runtime; repo holds no game data. |
| **Test Command** | No unit tests. Gates: `tools/check-vanilla-plus.sh` (reduced suite: docs_gate + marker census + LF check), owner's Win11 build is the compile gate of record. |

**Scale:** ~771K LOC under `Source/` — almost all of it **generated** from Ghidra recovery (`// Auto-generated by ghidra-mcp - DO NOT EDIT`). The hand-written surface is small: ~2,700 lines in `Redivivus/`, ~4,900 lines of fork-owned TUs, and 147 `// VP-BEGIN` regions across 49 upstream files.

## Execution Lifecycle (boot → play)

```
1. Static-init ladder (init_priority): 130 boot log → 140 crash VEH → 150 trace → 200 static-init runner
2. Game/Main.cpp boot: mode store → hangwatch arm → ALTTOGGLE_EnsureIni (creates d2vp.ini template via CREATE_NEW) → SFile/MPQ load → GFX/window/sound → D2BOOT_Fail+return at each gate failure
3. First config read anywhere → 2 s poll gate: GetPrivateProfileIntA("features", key, 0, <exe dir>\d2vp.ini); missing file/section/key = 0 = vanilla behavior
4. Options-page toggle → D2VP_SetFeatureToggle → WritePrivateProfileStringA + D2VP_ConfigReloaded (zeroes every gate's tick static)
5. Feature activation per layer: client draw/click sites gated in D2Client/D2Win/D2gfx TUs; server logic (stash, mana burn, 0x4F/0x7D) gated in D2Game TUs, which poll the ini independently (≤2 s lag; D2Game cannot import D2Client)
6. Shared stash page flip: client sends C→S 0x4F button 0x7D (page in the gold-amount param word) → PlayerTrade.cpp intercept → server swaps materialized item units; save flush hooks SaveGameAllGameTypes (PlayerSave.cpp:1129–1134)
7. Every present: UNLOCKFPS_StatsIfDue logs presents/ticks to d2boot.log every 5 s; interp delta computed once per present, shared by all rider sites
8. Crash: VEH → d2crash-*.txt (symbolised from the image's own DWARF) → also mirrored into d2boot.log
```

## Patterns & Conventions

| Aspect | Pattern |
|--------|---------|
| Fork edits | Ride between `// VP-BEGIN` / `// VP-END` with issue#/round tags (`[R153]`, `[#37]`); new code goes in fork-only TUs — upstream files never grow new code |
| Feature gating | Static `int` cache + static `DWORD` tick, `GetTickCount` 2 s poll, `GetPrivateProfileIntA` default 0; unsigned wrap-safe subtraction; identical skeleton in 14 gates |
| Defaults | Vanilla by default: no ini/section/key = retail byte-for-byte; every feature opt-in OFF; sole exception `unlock_fps_interp` (default 1) |
| Safety | Merge tripwires: `static_assert`s on struct size/offsets/enum values + runtime `VANILLAPLUS_SelfCheck` that scans wired tables and `exit(-1)`s loudly to d2boot.log at boot time |
| File writes | `CREATE_NEW` for templates (never clobber); temp+flush+`MoveFileExA(REPLACE_EXISTING)`+one `.bak` generation for the stash |
| Layout | Click bands computed from the same measured widths the draw uses — no stored geometry to go stale |
| Docs lanes | Human: README/CHANGELOG/SMOKE (concise). Agent: handoff.md (16 KB budget), HISTORY.md, plans/, FEATURES.md (verbose) |
| Versioning | Code rounds R###, not semver; round in `D2VP_ROUND` (Redivivus/d2_boot.h, currently "161"); bump via `tools/round_bump.py` |

## Known Landmines

- **Generated tree** — everything under `Source/` is ghidra-mcp output; upstream syncs are RETIRED (owner 2026-11-09) so the fork edits source directly, but a wholesale regen would still clobber VP regions. The markers are the fork's insurance.
- **Adding a feature = 4 coordinated edits**: (1) `gaVanillaPlusRows` entry, (2) gate accessor in VanillaPlusCore.cpp, (3) template block in `ALTTOGGLE_WriteIniTemplate`, (4) bust line in `D2VP_ConfigReloaded` — with the tick static declared **before** Core.cpp:1534. The comment at Options.cpp:149–153 ("+1 entry here and +1 template block — nothing else") understates it.
- **`wvsprintfA` has a 1024-char OUTPUT limit, not a destination limit** — `BootLogWrite` formats into `szBuf[640]` and `D2BOOT_MarkFmt` into `szBody[512]`; diagnostics now pre-truncate inputs (R161).
- **`SGAMEDATA` ownership pin is pointer-identity** (`VPSHARED_EnsureOwner`, VanillaPlusStash.cpp:195-201) — allocator address reuse resurrects stale pool pointers (ROB-03 deferred).
- **Personal stash is memory-only while a shared page is active** — freed units at toggle, only serialized block in BSS; any exit that skips `SaveGameAllGameTypes` (crash, kill) loses the personal stash set deposited before the toggle (documented R161).
- **The 0x4F param word doubles as gold-amount and page number** (`PlayerTrade.cpp:2569–2570`) — don't "clean up" without knowing.
- **Static-init priority ladder** (130/140/150/200 in Redivivus/) is load-bearing: renumbering breaks "boot log exists before the VEH can fire".
- **`d2_control.cpp` DEV channel**: binds 127.0.0.1:7777 loopback only with `hex` (arbitrary read), `shot` (arbitrary file write), `cpkt` (raw packets), `watch`/`guard` (VirtualProtect). Release builds remove the TU from the build — but never build a distributable with `REDIVIVUS_DEV=ON`.
- **Unbalanced VP markers**: All 149 BEGIN/149 END markers are balanced (R161 fixes resolved unbalanced markers).
- **`GetPrivateProfileIntA` cache quirk**: after the first in-process `WritePrivateProfileStringA`, external ini edits may stop being seen (Windows profile cache) — documented in R161 with user feedback on write failures.
- **Glyph layout reads through `abUnverified` fields at magic offsets** (Core.cpp:1662, Options.cpp:499) — layout drift fails silently (wrong font pick), not loudly.
- **Windows profile cache limitations**: External ini editing may not be reflected until game restart (documented in R161).

## Active Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Upstream sync | Retired; fork improves recovered source directly | Owner 2026-11-09: "unlikely we are going to be merging again" |
| Fork code placement | Fork-only TUs + VP-marked thin sites | Keeps upstream diffs auditable; markers survive regen |
| Byte-matching | Out of scope for this fork | Lives upstream; fork optimizes for playability + QoL |

| Save formats | `.d2s`/`.d2x` untouched; stash in its own `_d2vp_shared.sss` | Characters stay retail-compatible (invariant I1: shared bytes never reach a .d2s) |
| Rendering | Vulkan via separate Glide3xVK repo (`glide3x.dll`) | Keeps this repo game-logic only |
| Choke-point fixes | Fix at `CUnit::RemoveObject` etc. rather than ~30 call sites | Covers every free path including future ones |
| Scope | Single-player only; BNet unsupported | Not designed/tested for online |
| Audit approach | Incremental rounds addressing findings as identified | Balance between comprehensive fixes and iterative progress |

## Recent Major Improvements (R159-R161)

### Security Hardening (R159, R161)
- **DEV Control Channel**: Binds loopback only (127.0.0.1:7777) preventing external network access
- **Input Guards**: Added bounds checking for all remote control commands (`mon`/`watch`/`ai`/`walldir`/`objname`/`setclip`)
- **Path Safety**: Eliminated buffer overflow risks in Redivivus boot path assembly with comprehensive bounds checking
- **Deprecated Unsafe Commands**: Retired `sym` command help stub to remove potential attack surface

### Data Integrity & Robustness (R160)
- **Shared Stash Protection**: Added transient read failure prevention - refuses operations when `_d2vp_shared.sss` is temporarily unavailable
- **Partial Materialization Recovery**: Enhanced error handling preserves existing state when page materialization fails
- **Automatic Recovery**: System defers operations and refuses saves until successful reads occur

### Enhanced Error Handling (R161)
- **INI Write Feedback**: Comprehensive user feedback for settings save failures (sound + visual indicators)
- **Buffer Safety**: Enhanced buffer bounds checking throughout crash logging and boot systems
- **Documentation**: Added Windows profile cache limitations and improved ini handling documentation
- **Self Check Relocation**: `VANILLAPLUS_SelfCheck` now runs at boot time, not mid-game

### Performance & UX Improvements (R161)
- **Options Page Optimization**: Reduced from 16 individual polls per frame to 1 batch poll, eliminating draw stutter
- **Enhanced Caching**: Improved ini polling efficiency when Options page is open
- **Visual Feedback**: Restart settings indicators and settings save feedback systems

### Code Quality Improvements
- **VP Marker Balance**: Fixed all unbalanced VP markers (149 BEGIN/149 END maintained)
- **Memory Safety**: Automated verification of Redivivus boot pattern memory safety
- **Version Consistency**: Dynamic version tag system prevents hardcoded version drift

## Quick Start for Developer

1. Read `CONTRIBUTING.md` house rules first — they are enforced culturally and by docs_gate.
2. Touching settings/UI → `VanillaPlusCore.cpp` + `VanillaPlusOptions.cpp`; stash/save → `VanillaPlusStash.cpp` + `SFile.cpp`; rendering → the VP regions in `Gfx.cpp`/`Wall2.cpp`/`View.cpp`.
3. Never edit generated code outside VP markers; every fork edit gets `[R###]`/`[#issue]` tagging and, for a new feature, the 4-edit checklist (Landmines above).
4. Check `handoff.md` §7 before doing anything — it lists exactly which field debts are open; update it (16 KB budget) and CHANGELOG per docs policy.
5. Build identically to the owner: mingw-w64 i686, `-O0 -g` (or `REDIVIVUS_LEAN=ON`), never an optimizing build type (decompiled code may lean on UB).
