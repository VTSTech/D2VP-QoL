## Execution Lifecycle (boot → play)

```
1. Static-init ladder (init_priority): 130 boot log → 140 crash VEH → 150 trace → 200 static-init runner
2. Game/Main.cpp boot: mode store → hangwatch arm → ALTTOGGLE_EnsureIni (creates d2vp.ini template via CREATE_NEW) → SFile/MPQ load → GFX/window/sound → D2BOOT_Fail+return at each gate failure
3. First config read anywhere → 2 s poll gate: GetPrivateProfileIntA("features", key, 0, <exe dir>\d2vp.ini); missing file/section/key = 0 = vanilla behavior
4. Options-page toggle → D2VP_SetFeatureToggle → WritePrivateProfileStringA + D2VP_ConfigReloaded (zeroes every gate's tick static)
5. Feature activation per layer: client draw/click sites gated in D2Client/D2Win/D2gfx TUs; server logic (stash, mana burn, 0x4F/0x7D) gated in D2Game TUs, which poll the ini independently (≤2 s lag; D2Game cannot import D2Client)
6. Shared stash page flip: client sends C→S 0x4F button 0x7D (page in the gold-amount param word) → PlayerTrade.cpp intercept → server swaps materialized item units; save flush hooks SaveGameAllGameTypes (PlayerSave.cpp:1129–1134)
7. Every present: UNLOCKFPS_StatsIfDue logs presents/ticks to d2boot.log every 5 s; interp delta computed once per present, shared by all rider sites
8. Crash: VEH → d2crash-*.txt (symbolised from the image's own DWARF) → also mirrored into d2boot.log
```

## Patterns & Conventions

| Aspect | Pattern |
|--------|---------|
| Fork edits | Ride between `// VP-BEGIN` / `// VP-END` with issue#/round tags (`[R153]`, `[#37]`); new code goes in fork-only TUs — upstream files never grow new code |
| Feature gating | Static `int` cache + static `DWORD` tick, `GetTickCount` 2 s poll, `GetPrivateProfileIntA` default 0; unsigned wrap-safe subtraction; identical skeleton in 14 gates |
| Defaults | Vanilla by default: no ini/section/key = retail byte-for-byte; every feature opt-in OFF; sole exception `unlock_fps_interp` (default 1) |
| Safety | Merge tripwires: `static_assert`s on struct size/offsets/enum values + runtime `VANILLAPLUS_SelfCheck` that scans wired tables and `exit(-1)`s loudly to d2boot.log |
| File writes | `CREATE_NEW` for templates (never clobber); temp+flush+`MoveFileExA(REPLACE_EXISTING)`+one `.bak` generation for the stash |
| Layout | Click bands computed from the same measured widths the draw uses — no stored geometry to go stale |
| Docs lanes | Human: README/CHANGELOG/SMOKE (concise). Agent: handoff.md (16 KB budget), HISTORY.md, plans/, FEATURES.md (verbose) |
| Versioning | Code rounds R###, not semver; round in `D2VP_ROUND` (Redivivus/d2_boot.h, currently "158"); bump via `tools/round_bump.py` |

## Known Landmines

- **Generated tree** — everything under `Source/` is ghidra-mcp output; upstream syncs are RETIRED (owner 2026-11-09) so the fork edits source directly, but a wholesale regen would still clobber VP regions. The markers are the fork's insurance.
- **Adding a feature = 4 coordinated edits**: (1) `gaVanillaPlusRows` entry, (2) gate accessor in VanillaPlusCore.cpp, (3) template block in `ALTTOGGLE_WriteIniTemplate`, (4) bust line in `D2VP_ConfigReloaded` — with the tick static declared **before** Core.cpp:1534. The comment at Options.cpp:149–153 ("+1 entry here and +1 template block — nothing else") understates it.
- **`wvsprintfA` has a 1024-char OUTPUT limit, not a destination limit** — `BootLogWrite` formats into `szBuf[640]` and `D2BOOT_MarkFmt` into `szBody[512]`; a long crash line can overrun ~390 bytes on the dying path (d2_boot.cpp:50-51, d2_crash.cpp:192).
- **`SGAMEDATA` ownership pin is pointer-identity** (`VPSHARED_EnsureOwner`, VanillaPlusStash.cpp:195-201) — allocator address reuse resurrects stale pool pointers.
- **Personal stash is memory-only while a shared page is active** — freed units at toggle, only serialized block in BSS; any exit that skips `SaveGameAllGameTypes` (crash, kill) loses the personal stash set deposited before the toggle.
- **The 0x4F param word doubles as gold-amount and page number** (`PlayerTrade.cpp:2569-2570`) — don't "clean up" without knowing.
- **Static-init priority ladder** (130/140/150/200 in Redivivus/) is load-bearing: renumbering breaks "boot log exists before the VEH can fire".
- **`d2_control.cpp` DEV channel**: binds 0.0.0.0:7777 unauthenticated with `hex` (arbitrary read), `shot` (arbitrary file write), `cpkt` (raw packets), `watch`/`guard` (VirtualProtect). Release builds remove the TU from the build — but never build a distributable with `REDIVIVUS_DEV=ON`.
- **Unbalanced VP markers**: `D2Client.cpp:1815`, `ui.cpp:8952`, `Wall2.h:63` have `VP-BEGIN` with no `VP-END` — latent docs_gate §8 failures the next time those files change.
- **`GetPrivateProfileIntA` cache quirk**: after the first in-process `WritePrivateProfileStringA`, external ini edits may stop being seen (Windows profile cache) — the "external editor hot-read" contract can silently break.
- **Glyph layout reads through `abUnverified` fields at magic offsets** (Core.cpp:1662, Options.cpp:499) — layout drift fails silently (wrong font pick), not loudly.

## Active Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Upstream sync | Retired; fork improves recovered source directly | Owner 2026-11-09: "unlikely we are going to be merging again" |
| Fork code placement | Fork-only TUs + VP-marked thin sites | Keeps upstream diffs auditable; markers survive regen |
| Byte-matching | Out of scope for this fork | Lives upstream; fork optimizes for playability + QoL |
| Feature defaults | All OFF, ini hot-polled ~2 s, in-game Options page | "Nothing silently changes gameplay" charter |
| Save formats | `.d2s`/`.d2x` untouched; stash in its own `_d2vp_shared.sss` | Characters stay retail-compatible (invariant I1: shared bytes never reach a .d2s) |
| Rendering | Vulkan via separate Glide3xVK repo (`glide3x.dll`) | Keeps this repo game-logic only |
| Choke-point fixes | Fix at `CUnit::RemoveObject` etc. rather than ~30 call sites | Covers every free path including future ones |
| Scope | Single-player only; BNet unsupported | Not designed/tested for online |

## Quick Start for Developer

1. Read `CONTRIBUTING.md` house rules first — they are enforced culturally and by docs_gate.
2. Touching settings/UI → `VanillaPlusCore.cpp` + `VanillaPlusOptions.cpp`; stash/save → `VanillaPlusStash.cpp` + `SFile.cpp`; rendering → the VP regions in `Gfx.cpp`/`Wall2.cpp`/`View.cpp`.
3. Never edit generated code outside VP markers; every fork edit gets `[R###]`/`[#issue]` tagging and, for a new feature, the 4-edit checklist (Landmines above).
4. Check `handoff.md` §7 before doing anything — it lists exactly which field debts are open; update it (16 KB budget) and CHANGELOG per docs policy.
5. Build identically to the owner: mingw-w64 i686, `-O0 -g` (or `REDIVIVUS_LEAN=ON`), never an optimizing build type (decompiled code may lean on UB).
